# 优化质检驳回理由查询算法 - 设计文档

## 概述
本文档详细描述了优化质检驳回理由查询算法的技术设计，包括问题分析、解决方案设计和实现细节。

## 问题分析

### 现有问题
1. **元素定位依赖硬编码ID模式**：
   - 关闭通知按钮依赖 `*[id$="_244"]` 模式
   - 信息图标依赖 `*[id$="_197"]` 模式
   - 当页面结构变化时，这些模式可能失效

2. **DOM元素查询策略过于宽泛**：
   - 信息图标定位使用了过于宽泛的选择器 `[class*="info"], [class*="icon"]`
   - 这些选择器会匹配到无关元素（如"标注要求"），导致定位错误

3. **缺乏基于SVG内容的精确定位**：
   - 未利用用户提供的SVG路径信息进行精确定位
   - 无法通过SVG内容特征区分相似的元素

4. **文本提取逻辑不够健壮**：
   - 简单的文本匹配容易受页面其他内容干扰
   - 缺乏对复杂文本结构的处理能力

5. **错误处理机制不完善**：
   - 缺乏详细的错误信息和日志记录
   - 没有有效的降级策略

## 解决方案设计

### 1. 增强的DOM元素定位策略

#### 多层次定位方法
```
1. 优先级1: 精确ID匹配
   - 使用原有的ID模式匹配作为最精确的定位方法
   - 例如: `[id$="_197"]` 用于信息图标，`[id$="_244"]` 用于关闭按钮

2. 优先级2: SVG内容特征匹配
   - 基于SVG路径数据精确定位SVG元素
   - 使用用户提供的SVG路径信息进行匹配
   - 避免匹配到无关元素（如"标注要求"）

3. 优先级3: 特定类名和属性匹配
   - 使用特定的CSS类名和属性进行定位
   - 避免使用过于宽泛的选择器
   - 例如: `.anticon-info-circle` 用于信息图标

4. 优先级4: 结构化定位
   - 基于DOM树结构的相对定位
   - 使用父子关系和兄弟关系进行元素查找
   - 例如: 在特定容器内查找子元素

5. 优先级5: XPath定位
   - 使用XPath表达式进行精确定位
   - 可以包含复杂的条件判断
   - 例如: `//span[contains(@class, "anticon") and contains(@aria-label, "info") and not(contains(text(), "标注"))]`

6. 优先级6: 回退到现有方法
   - 保持现有的ID模式匹配作为最后手段
```

#### 精确元素识别
- 避免使用过于宽泛的选择器（如 `[class*="info"]`）
- 使用SVG内容特征进行精确定位
- 使用特定的类名和属性进行精确定位
- 实现基于元素上下文的智能识别算法
- 添加元素验证机制，确保定位的元素是目标元素

### 2. 改进的文本内容提取逻辑

#### 多策略文本提取
```
1. 结构化提取
   - 识别并解析特定的数据结构
   - 提取结构化数据而非原始文本

2. 上下文感知提取
   - 根据元素的上下文环境提取相关信息
   - 使用自然语言处理技术识别关键信息

3. 容错性提取
   - 处理不完整或格式异常的文本
   - 提供多种提取方法并选择最佳结果
```

#### 文本清理和标准化
- 实现文本清理功能，去除无关字符和空白
- 标准化文本格式，统一处理不同编码和特殊字符
- 添加文本验证机制，确保提取内容的有效性

### 3. 完善的错误处理和降级机制

#### 分层错误处理
```
1. 元素定位失败
   - 记录详细的定位失败信息
   - 尝试备选定位策略
   - 提供友好的错误提示

2. 文本提取失败
   - 记录提取失败的原因
   - 使用默认值或空值处理
   - 提供手动输入选项

3. 整体流程失败
   - 保持原有功能的可用性
   - 提供详细的错误日志
   - 支持手动触发重试
```

#### 降级策略
- 实现多级降级机制，确保在部分功能失效时仍能提供基本功能
- 提供手动操作选项，允许用户在自动提取失败时手动输入
- 添加配置选项，允许用户自定义提取策略
