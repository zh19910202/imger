# 优化质检驳回理由查询算法

## Status
Proposed

## Summary
本提案旨在优化当前质检驳回理由的查询算法，通过改进两步交互模式和DOM元素定位策略，提高驳回理由提取的准确性和稳定性。现有的实现依赖于硬编码的元素ID模式和简单的文本匹配，这在页面结构变化时容易失效。

## Why
当前的质检驳回理由查询算法存在以下问题：

1. **可靠性不足**：依赖于特定的元素ID模式（如UID模式：*_244关闭按钮，*_197信息图标），当页面结构变化时容易失效
2. **准确性有限**：使用简单的文本匹配和XPath/CSS选择器，难以适应复杂的页面结构
3. **维护困难**：硬编码的选择器和ID模式使得代码难以维护和扩展
4. **用户体验不佳**：在提取失败时缺乏有效的降级策略和错误处理

## What Changes
通过优化查询算法，可以：
- 提高驳回理由提取的成功率和准确性
- 增强代码的健壮性和适应性
- 改善用户在处理返修题时的体验
- 减少因页面结构变化导致的功能失效

## Technical Design
### Components Affected
- `/src/appen-data-collector.js` - 主要的质检驳回理由查询和处理逻辑

### New Components
- 无新增组件

### API Changes
- 无API变更

## Implementation Plan
1. 分析现有查询算法的实现细节和问题点
2. 设计改进的DOM元素定位策略
3. 实现增强的文本内容提取逻辑
4. 添加更完善的错误处理和降级机制
5. 测试在不同页面结构下的兼容性
6. 验证优化后的算法在实际使用中的效果

## Testing Strategy
- 单元测试：验证新的DOM定位和文本提取逻辑
- 集成测试：在模拟的不同页面结构下测试查询算法
- 实际测试：在真实的返修题页面上验证功能
- 回归测试：确保优化不影响其他功能

## Security Considerations
- 无重大安全影响
- 保持现有的数据访问和处理权限

## Backward Compatibility
- 保持与现有接口的兼容性
- 提供降级机制确保在新算法失效时仍能工作

## Alternatives Considered
1. **完全重构查询机制**：重新设计整套查询机制，但成本较高且风险较大
2. **增加更多硬编码选择器**：通过增加更多选择器提高匹配率，但会增加维护成本
3. **使用机器学习方法**：训练模型识别驳回理由元素，但实现复杂且需要大量训练数据

选择当前方案是因为它在改进效果和实现成本之间取得了较好的平衡。
