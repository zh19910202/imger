# 数据看板设计文档

## 系统架构

### 数据流架构

```
completionStats (内存) 
    ↓
localStorage (本地存储)
    ↓
历史数据库 (IndexedDB/localStorage)
    ↓
统计报表引擎 (聚合计算)
    ↓
看板展示层 (UI/图表)
```

### 核心模块

#### 1. 统计数据管理模块
- **功能**: 管理标注数据的统计和聚合
- **存储**: 
  - 日粒度数据: localStorage (格式: `appen_daily_stats_YYYY-MM-DD`)
  - 聚合数据: 内存 + localStorage 缓存

#### 2. 报表生成引擎
- **功能**: 支持多维度的统计报表生成
- **维度**: 日、周、月、自定义范围
- **聚合指标**:
  - 总完成数、有效/无效比率
  - 平均耗时、总耗时
  - 做题总数、按题目分布
  - 返修数据、质检驳回率

#### 3. 数据可视化层
- **图表类型**:
  - 柱状图: 日完成数对比
  - 折线图: 每日趋势
  - 饼图: 有效/无效分布
  - 表格: 详细数据列表
- **交互方式**:
  - 时间范围选择
  - 数据钻取
  - 导出功能

## 存储策略

### localStorage 设计

```
appen_daily_stats_YYYY-MM-DD: {
  // 日粒度数据
}

appen_weekly_stats_YYYY-Www: {
  // 周粒度缓存数据（可选）
}

appen_monthly_stats_YYYY-MM: {
  // 月粒度缓存数据（可选）
}

appen_stats_meta: {
  lastUpdate: timestamp,
  version: 2,
  dataRetentionDays: 90
}
```

### 数据保留策略
- 日粒度: 保留 90 天
- 周粒度: 计算生成，无独立存储
- 月粒度: 计算生成，无独立存储
- 自动清理: 超过保留期的数据自动删除

## 计算逻辑

### 周报表计算

```
查询条件: 指定周次 (ISO 8601 Week Number)
1. 计算周一和周日的日期
2. 从 localStorage 加载该周所有日期的日粒度数据
3. 按字段求和聚合
4. 计算平均值和百分比
```

### 月报表计算

```
查询条件: 指定月份 (YYYY-MM)
1. 确定该月的起止日期
2. 从 localStorage 加载该月所有日期的日粒度数据
3. 按字段求和聚合
4. 计算周分解数据
5. 计算平均值和百分比
```

### 自定义范围计算

```
查询条件: startDate 和 endDate
1. 验证日期范围有效性
2. 从 localStorage 加载范围内所有日期数据
3. 按字段求和聚合
4. 计算指标和趋势
```

## 数据同步

### 与服务端同步策略

```
本地数据 (completionStats) 
    ↓ (实时)
日粒度存储 (localStorage)
    ↓ (定时，如有配置)
服务端接口 (GetUserTaskDetails)
    ↓
服务端报表数据库
```

**同步时机**：
- 实时: 标注完成后更新本地日粒度数据
- 定时: 可选的后台同步（通过 pushData）
- 用户触发: 用户主动请求服务端数据时

## 性能考虑

### 查询优化
- 日粒度数据按日期索引
- 使用缓存减少重复计算
- 大数据集使用虚拟滚动

### 存储优化
- 压缩历史数据
- 按月归档数据
- 定期清理过期数据

## 后续扩展

1. **数据导出**: CSV、Excel、PDF
2. **对标分析**: 与其他用户或历史平均水平对比

4. **实时监控**: WebSocket 实时数据更新
